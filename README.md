# Бар KDS для Poster

Экран заказов для бара. Он получает заказы из Poster со всех касс заведения и показывает их барменам. Система записывает, кто какую порцию приготовил, и строит отчёты для расчёта зарплаты: отдельно по продавцам (кто пробил) и по барменам (кто сделал).

- **Экран бара** `/kds/` работает в браузере на любом планшете, телефоне, ТВ или ПК и ставится на рабочий стол как приложение.
- **Админка** `/admin/` содержит отчёты, сотрудников, ставки, экраны, настройки и состояние связи с Poster.

## Как это работает

```
Кассы Poster (любое количество)
   │  вебхук «чек изменился»    — мгновенно
   │  опрос открытых чеков       — каждые 4 с (страховка)
   │  полная сверка за сутки     — каждые 60 с
   ▼
Сервер: сверяет текущий состав чека в Poster с тем, что уже на экране,
        и применяет разницу. Повторы и пропуски событий не создают дублей и не теряют заказы.
   ▼
PostgreSQL ── WebSocket ──► экраны бара (сколько угодно)
```

**Одна порция — одна строка.** Три мохито — это три строки, и их могут сделать разные бармены.

| Действие на экране | Что записывается |
|---|---|
| Касание новой позиции | «Взял: Иван» и время |
| Повторное касание | «Готово: Иван», время, ставка на этот момент |
| Касание чужой взятой позиции | после подтверждения засчитывается тому, кто отметил; в журнал пишется «перехват» |
| «Всё готово» | все оставшиеся позиции заказа |
| Отмена своей отметки | в течение 5 минут (настраивается `UNDO_WINDOW_SEC`), только тем же барменом |

**Заказ на экране показывает:** стол, номер чека, кто пробил, кассу, количество гостей, комментарий, модификаторы и таймер (жёлтый через 5 минут, красный через 10). Дозаказ к тому же столу приходит отдельной карточкой с пометкой «ДОЗАКАЗ».

**Если позицию убрали из чека в Poster,** система отменяет порции в таком порядке: сначала ещё не начатые, потом взятые, потом готовые. Готовая порция, которую потом удалили, помечается «сделано → удалено». Бармену она по умолчанию засчитывается и попадает во вкладку «Контроль»: это главный признак потерь в баре.

## Отчёты

- **Бармены:** порции, начислено по сдельным ставкам, число чеков, среднее время приготовления и ожидания гостя.
- **Продажи:** кто пробил, сколько закрыто чеков, оплаченная сумма, средний чек, барные порции. Данные берутся из закрытых чеков Poster.
- **Позиции:** что и сколько приготовлено, среднее время.
- **Все порции:** по каждой порции видно, кто продал, кто взял, кто сделал, время и ставка. Можно отфильтровать по сотруднику.
- **Контроль:** сделано и удалено из чека; порции, висящие больше 30 минут; перехваты; ручные исправления.
- Все отчёты выгружаются в Excel (CSV с разделителем `;`). Период считается рабочими днями: с 06:00 до 06:00, начало настраивается.
- Ставка фиксируется в момент отметки «готово». Если поменять ставку, прошлые начисления не пересчитываются.
- Ручное исправление «кто сделал» возможно только с указанием причины и всегда пишется в журнал.

## Запуск

```bash
cp .env.example .env      # заполнить POSTER_TOKEN, ADMIN_PASSWORD, APP_SECRET, DB_PASSWORD
docker compose up -d --build
```

Сервис поднимается на порту 3000. Нужен публичный HTTPS-адрес, чтобы Poster мог присылать вебхуки, например nginx/Caddy перед сервисом или Cloudflare Tunnel. База каждую ночь копируется в `./backups`, копии хранятся 30 дней.

## Подключение к Poster

1. **Токен.** Его можно взять в Poster в разделе «Доступ → Интеграция» или создать приложение на dev.joinposter.com и получить токен через OAuth. Укажите его в `POSTER_TOKEN`.
2. **Вебхуки.** В настройках приложения в dev-кабинете укажите адрес `https://ваш-домен/webhooks/poster` и подпишитесь на изменения чеков (`transaction`), а также товаров и сотрудников. В `POSTER_APP_SECRET` впишите `application_secret`. Без вебхуков система тоже работает, только задержка будет до 4 секунд.
3. **Админка → «Настройки»:** отметьте цех «Бар». Тогда на экран пойдут только барные позиции.
4. **Админка → «Сотрудники»:** официанты и кассиры подтягиваются из Poster сами. Отметьте барменов и выдайте каждому PIN. Бармена, которого нет в Poster, можно добавить вручную.
5. **Админка → «Ставки»:** задайте сдельную ставку за каждую позицию.
6. **Админка → «Экраны»:** создайте экран и откройте выданную ссылку на самом планшете. Ссылка показывается один раз. Потерянный планшет можно отключить там же.
7. **Админка → «Состояние» → «Загрузить историю»:** подтягивает прошлые продажи в отчёт по продавцам.

### Что проверить на реальном аккаунте в первый день

Интеграция писалась по документации API Poster (`dash.getTransactions`, `dash.getTransaction`, `menu.getProducts`, `menu.getWorkshops`, `access.getEmployees`). Названия полей у разных версий API немного отличаются, поэтому все чтения идут через `src/poster/normalize.js` с запасными вариантами. Сырые ответы сохраняются в `transactions.raw` и `webhook_log`. Проверьте следующее:

- [ ] На экране правильно отображаются стол, официант и касса. Если нет, сверьте поля в `transactions.raw` и поправьте `normalize.js`.
- [ ] Модификаторы (например, «овсяное молоко») показываются названием, а не номером.
- [ ] Суммы в отчёте «Продажи» совпадают с Poster. Если они в 100 раз больше или меньше, поменяйте `POSTER_MONEY_DIVISOR`.
- [ ] Во вкладке «Состояние» вебхуки приходят с отметкой «Подпись: ok». После этого можно включить `POSTER_WEBHOOK_STRICT=true`.
- [ ] Позиции весового товара, например «0,05 л», приходят одной строкой с количеством.

Сейчас позиция появляется на экране, как только её пробили в чек. Если нужно, чтобы она появлялась только после нажатия «Отправить в цех» или печати бегунка, эту логику можно добавить после проверки, как Poster передаёт это событие в истории чека на вашем аккаунте.

## Надёжность

- Источник истины — Poster. Каждое событие перепроверяется запросом к API, поэтому поддельный или потерянный вебхук не ломает данные.
- Сверка идемпотентна: вебхук, опрос и полная сверка одного и того же чека не создают дублей. Это покрыто тестами.
- Одновременные нажатия двух барменов на одну порцию засчитываются ровно одному. Работает через блокировки строк в PostgreSQL.
- Если на планшете пропал Wi-Fi, нажатия копятся в очереди и отправляются, когда связь вернётся. У каждого нажатия свой `op_id`, поэтому повторная отправка не задваивает отметку.
- На экране всегда видно состояние: «Poster: онлайн», «Нет связи с Poster» или «Нет связи с сервером», а также число неотправленных нажатий.
- Если экран пропустил push-уведомление, он всё равно перечитывает доску каждые 15 секунд.
- Старые чеки (больше 12 часов, `KDS_MAX_AGE_HOURS`) и загрузка истории не засоряют экран.
- Любое действие пишется в журнал: кто, когда, с какого экрана и с какой позицией.

## Разработка

```bash
npm install
npm test                      # нужен PostgreSQL, база kds_test (DATABASE_URL)
npm run mock-poster           # имитация Poster на :4100
POSTER_API_URL=http://localhost:4100/api POSTER_TOKEN=demo npm start
npm run simulate              # случайные заказы в имитацию
```

Структура:

```
src/poster/      клиент API Poster, нормализация полей, проверка вебхуков
src/sync/        reconcile.js — сверка чека с экраном; engine.js — вебхуки, опрос, очередь
src/units.js     действия барменов (взял / готово / вернул / отменил)
src/reports.js   отчёты и CSV
src/app.js       HTTP API экрана и админки
public/kds/      экран бара (PWA, без сборки)
public/admin/    админка
test/            тесты и имитация Poster
```
